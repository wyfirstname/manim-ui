### WebGPU 适配器详情（实测）

```
vendor: intel    architecture: gen-9    device: Intel UHD 630
features: shader-f16, float32-filterable, float32-blendable,
          bgra8unorm-storage, depth-clip-control, texture-compression-bc,
          dual-source-blending, timestamp-query, clip-distances,
          depth32float-stencil8, rg11b10ufloat-renderable, indirect-first-instance
limits: maxBufferSize 2GB | maxStorageBufferBindingSize ~2GB | maxTextureDimension2D 16384
```

`clip-distances` 这一项尤其重要——**manim 的 3D 裁剪平面功能直接依赖它**，本机原生支持。

### ⚠️ 关键教训：WebGPU 必须跑在安全上下文

**第一次实测曾误判"WebGPU 不可用"，根因是测试方法错误：**

WebGPU 规范要求**安全上下文**（HTTPS 或 `http://localhost`）。在 `about:blank` 页面上，
浏览器会直接**隐藏** `navigator.gpu` 属性（值为 `undefined`），而不是"存在但请求适配器失败"。

```
about:blank  →  isSecureContext: false, origin: "null"  →  navigator.gpu === undefined ❌误判
http://127.0.0.1:7788  →  isSecureContext: true       →  navigator.gpu 正常  ✅
```

**判别口诀**：
- `navigator.gpu === undefined` → 是上下文/浏览器问题，换安全上下文再试
- `navigator.gpu` 存在但 `requestAdapter()` 返回 `null` → 才是硬件/驱动不支持

**这对产品有直接影响**：本项目是 `localhost` 本地服务，天然满足安全上下文，无此问题。

### 端到端验证：manim 原始 WGSL 在 WebGPU 上跑通

已将 `3b1b/manim` 的 `manimlib/shaders/mandelbrot_fractal.wgsl`（3435 字符，**未做任何改写**）
在 WebGPU 上编译并渲染成功，仅需展开 manim 自己的 `#INSERT` 模板机制
（对照 `manimlib/renderer/shader_source.py` 的 `get_shader_code`）。

- WGSL 编译：**通过，零错误零警告**
- 绘制覆盖率：61.9%
- 产物：正确的曼德博集合（黑色主体 + 逃逸时间色带 + 分形海岸线）

验证文件：`docs/验证-WebGPU可用性.html`（双击即可打开复现）
着色器原件：`docs/mandelbrot_fractal.wgsl`

### 需要注意的实现细节

| 事项 | 说明 |
|---|---|
| **安全上下文** | 必须用 `localhost` / `127.0.0.1`，不能 `file://` |
| **uniform 对齐** | WGSL uniform block 按 16 字节对齐，`vec3f` 后需补`f32`；结构体总大小须为 16 的倍数 |
| **#INSERT 顺序** | `DATA_STRIDE` 等常量必须在引用它的代码之前展开 |
| **顶点数据布局** | manim 用 flat float 数组 + `read_data.wgsl` 自索引，不传顶点属性 |
| **离屏渲染** | 调试时用 `copyTextureToBuffer` 读回像素，比抓 canvas 可靠 |

## 二、技术选型（v2 已简化）

### 2.1 架构：本地服务 +浏览器 WebGPU 直连

```
┌──────────────────────────────────────────────┐
│  浏览器（Chromium 内核，localhost 安全上下文）   │
│  ┌────────────────────────────────────────┐  │
│  │ UI：场景库 / 参数面板 / 动画控制          │  │
│  ├────────────────────────────────────────┤  │
│  │ WebGPU 渲染层                          │  │
│  │  ├─ 直接加载 manim 的 .wgsl 着色器 ★    │  │
│  │  ├─ uniform block / shared buffer 移植   │  │
│  │  └─ 交互：拖拽 / 滚轮 / 键盘│  │
│  └────────────────────────────────────────┘  │
└──────────────────┬───────────────────────────┘
                   │ HTTP (localhost)
┌──────────────────┴───────────────────────────┐
│  Python 本地服务                              │
│  ├─ 几何计算：numpy / scipy（ODE 数值解）       │
│  ├─ 场景状态与参数                           │
│  └─ 静态资源托管                              │
└──────────────────────────────────────────────┘
```

**相比 v1 的简化**：不再需要 WGSL→GLSL 转译层（省掉了最大的技术风险），
着色器可直接搬。浏览器端负责渲染，Python 端只做它擅长的 CPU 数值计算。

### 2.2 需要从 manim 移植的代码

| 模块 | 工作量 | 说明 |
|---|---|---|
| `shaders/*.wgsl` | **零改写** | 直接复用，只需实现 `#INSERT` 展开 |
| `renderer/shader_source.py` | 小 | 模板展开逻辑，约 100 行→ JS |
| `renderer/uniform_block.py` | 小 | 16 字节对齐打包规则，约 200 行 → JS |
| `renderer/gpu.py` | 中 | 设备管理/渲染通道/绘制命令，需改写为 WebGPU API |
| `renderer/shared_buffer.py` | 小 | 缓冲增长策略 |
| `mobject/interactive.py` | 中 | 控件库，逻辑可翻译为 DOM/Canvas 实现 |
| `scene/interactive_scene.py` | 中 | 选择/成组/撤销状态机 |
| `mobject/*.py`（几何） | 中 | 曲线采样、曲面网格、ODE → 由 Python 端承担 |

**关键结论**：着色器（52KB，占技术难度的大头）**完全复用**，
需要改写的是 Python 侧的胶水层，总量可控。

## 五、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| **非安全上下文导致 WebGPU 不可见** | 高 | 已定位根因。产品必须用 `localhost` 服务，不能 `file://` 直接打开；启动器强制走 HTTP |
| 学生机器浏览器不支持 WebGPU | 中 | 首版要求 Edge/Chrome 113+；保留 WebGL2 降级提示（功能子集） |
| 学生机器无 Python | 中 | 附一键安装说明；后续出 PyInstaller 单文件版 |
| uniform 16 字节对齐踩坑 | 中 | 已实测确认规则，写入工具函数统一处理，避免散落各处 |
| Firefox/Safari 兼容性 | 低 | 首版明确仅支持 Chromium 内核 |
| 集显性能不足 | 低 | 实测单帧渲染 124ms（含首次编译），稳态远低于此，60fps 无压力 |
| 磁盘空间 | 低 | 已排除 Electron，纯静态资源占用小 |

### 安全上下文踩坑的防护措施（重要）

开发与使用中都**不能**用 `file://` 直接打开 HTML——那样 `navigator.gpu` 会静默消失，
表现为"我这台机器不支持 WebGPU"，极具误导性。

**防护做法**：
1. 启动器始终起HTTP 服务并打开 `http://127.0.0.1:<port>`
2. 页面加载时检测 `navigator.gpu` 是否存在，**不存在则明确提示**
   "请通过启动器打开（需要 localhost 环境）"，而非"显卡不支持"
3. 开发时用 `http://127.0.0.1:7788/` 而非 `file:///...` 做测试

## 七、v1 → v2 变更记录

| 项 | v1 结论（错误） | v2 实测结论 |
|---|---|---|
| WebGPU | 不可用 | ✅ 可用（gen-9，12 项特性） |
| 着色器策略 | 需 WGSL→GLSL 转译 | ✅ 原样复用，零改写 |
| 渲染后端 | WebGL2 | WebGPU（WebGL2 降级） |
| 架构复杂度 | 含转译层 | 移除转译层，大幅简化 |
| 错误根因 | 误判为硬件不支持 | **安全上下文要求**，非硬件问题 |

**教训**：浏览器新 API 的可用性判断，必须在正确的上下文（安全上下文、
真实 origin、非自动化干扰）下测试，否则容易得出完全错误的结论。
